## 2. Quick Start: Running the Visualizer

### 2.2 Basic interaction model (keyboard/mouse events that drive updates)

The visualizer windows in this application are all based on a Win32 message loop. Each window class implements a `wndProc` that intercepts keyboard and mouse messages (e.g. `WM_KEYDOWN`, `WM_MOUSEMOVE`, `WM_LBUTTONDOWN`, `WM_LBUTTONUP`, `WM_RBUTTONUP`) to drive interactive updates.  Most of the work is delegated to either:

- **CVoroguiWindow** (and its derivatives `CVorossWindow`, `CVorogsWindow`), which handles high-level key mappings, frame-capture toggles, and image-shuffle commands.
- **spivorogui** mouse handlers, invoked by `CVoroguiWindow::wndProc`, which interpret pointer actions over the Voronoï diagram (cell selection, control-level adjustment, label display) and trigger redraws.

#### Keyboard Controls

Within any Voronoï-based window (`CVoroguiWindow` and subclasses), pressing a key generates a `WM_KEYDOWN` that is handled as follows:

- **‘N’ (Next Image):**

Advances the slideshow to the next seed image (or next control state) and redraws the window.

```cpp
  case WM_KEYDOWN:
      if (wParam == 'N')
          SwitchToNextImage();
      else
          CVoroguiWindow::wndProc(hwnd, uMsg, wParam, lParam);
      return 0;
```

- **‘S’ (Save-Frames Toggle):**

Locates the attached `CImageWindow` or `CTimeframeWindow` and toggles its `skipsaveframes` flag. Subsequent timer events will then either capture or skip BMP frames.

- **‘W’ (Write Voronoï to Disk):**

Invokes `spivorogui::writetodisk()` to dump the current pointset (parameters and seed positions) to a text file.

- **‘1’ (Save Single Frame):**

Captures the current client area to a BMP file via `saveframetobmpfile()`, useful for on-demand screenshots.

- **‘Z’ / ‘X’ / ‘C’ / ‘V’ (Add/Remove Seed Controls)**  *(CVorossWindow only)*

These keys add or remove parameter-controls (“seed-sliders”) in batches of either the initial count or groups of 10. Each operation sets `_invalidatedib_flag = VOROGUI_INVALIDATEDIB_FORALLCONTROL` and forces a full redraw:

```cpp
  case WM_KEYDOWN:
      if (wParam == 'Z') add_ss(_initialnumberofadditional_ss);
      else if (wParam == 'X') remove_ss(_initialnumberofadditional_ss);
      else if (wParam == 'C') add_ss(10);
      else if (wParam == 'V') remove_ss(10);
      CVoroguiWindow::InvalidateDIB(NULL);
      RedrawWindow(_hwnd, NULL, NULL, RDW_INVALIDATE);
      return 0;
```

#### Mouse Controls

`CVoroguiWindow::wndProc` forwards raw mouse messages to the underlying `spivorogui` instance, which implements:

```cpp
case WM_MOUSEMOVE:    _pVOROGUI->onmousemove(hwnd, wParam, lParam);    return 0;
case WM_LBUTTONDOWN:  _pVOROGUI->onlbuttondown(hwnd, wParam, lParam); return 0;
case WM_LBUTTONUP:    _pVOROGUI->onlbuttonup(hwnd, wParam, lParam);   return 0;
case WM_RBUTTONUP:    _pVOROGUI->onrbuttonup(hwnd, wParam, lParam);   return 0;
```

- **Mouse-move (**`**onmousemove**`**)**

Tracks pointer speed and dwell time. When the pointer lingers over a control-cell long enough, it pops up a label window (`launchspitextwindow`) and invalidates only that control’s DIB region.

- **Left-button down (**`**onlbuttondown**`**)**

If neither Shift nor Ctrl is held, it computes which Voronoï cell was clicked and where within that cell. It then calculates a normalized ratio (0–1) along the cell’s vertical span and updates the corresponding `CParameter`, triggering a refresh of that control layer:

- **Left-button up (**`**onlbuttonup**`**)**

If Ctrl was held during a drag, it repositions a seed-point to the release coordinates, rebuilds the triangulation, and marks the entire canvas for redraw.

- **Right-button up (**`**onrbuttonup**`**)**

Toggles the display of text labels (if the click hits a control cell) or cycles the clustering mode for frame-points, then invalidates the full diagram.

#### Invalidation Flags

The member `_invalidatedib_flag` on `CVoroguiWindow` indicates precisely which part of the DIB buffer needs refreshing:

- `VOROGUI_INVALIDATEDIB_FORALLCONTROL`
- `VOROGUI_INVALIDATEDIB_FORONECONTROL`
- `VOROGUI_INVALIDATEDIB_FORONERANDOMCONTROL`
- `VOROGUI_INVALIDATEDIB_FOR50PCRANDOMCONTROL`

These flags allow efficient partial redraws when only a subset of controls has changed. Updates ultimately call `InvalidateDIB()` and `RedrawWindow(..., RDW_INVALIDATE)` on the window handle to schedule a `WM_PAINT`, where `CVoroguiWindow::UpdateDisplay` re-renders only the necessary layers.
