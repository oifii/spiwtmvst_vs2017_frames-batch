# 9. Troubleshooting & FAQ

### 9.2 ffmpeg fails or MP4 isn’t produced

When the automatic MP4 encoding step silently fails or no output video appears, follow these troubleshooting steps:

#### 9.2.1 Confirm the ffmpeg executable path

The application initializes its ffmpeg command path from the `FFMPEG_APP_PATH` macro. In your build or runtime environment, ensure that this macro points to a valid, standalone `ffmpeg.exe`. You can find this assignment in `CTimeframeWindow::Initialize` (and similarly in `CImageWindow::Initialize` and `CVoroguiWindow::Initialize`):

```cpp
// In CTimeframeWindow.cpp
//   global_ffmpegpath = "c:\\video\\ffmpeg.exe";
//   global_ffmpegpath = "d:\\spibin\\ffmpeg\\ffmpeg.exe";
global_ffmpegpath = FFMPEG_APP_PATH;
```

If `FFMPEG_APP_PATH` is unset or points to a non-existent file, the `system(...)` call will fail without obvious error. From a console, run:

```batch
"%FFMPEG_APP_PATH%" -version
```

to verify that your ffmpeg binary is found and operational.

---

#### 9.2.2 Verify output folder creation

Before invoking ffmpeg, the code creates the target directory using:

```cpp
_mkdir(global_outputvideofoldername.c_str());
```

By default, `global_outputvideofoldername` is set to a path like `d:\temp-spiwtmvstf-shuffle`. Make sure:

- The parent path exists and the process has write permissions.
- No typos exist in the folder name.
- On first run, inspect whether the directory appears. If it does not, ffmpeg will not find its output location and will silently exit.

---

#### 9.2.3 Inspect the generated ffmpeg command

For debugging, every ffmpeg invocation is written out to `commands.txt` right before execution:

```cpp
FILE* pFILE1 = fopen("commands.txt", "w");
if (pFILE1) {
    fprintf(pFILE1, "%s\n", systemcommand.c_str());
    fclose(pFILE1);
}
// then...
system(systemcommand.c_str());
```

Open `commands.txt` to see the exact command line. A typical example looks like:

```text
c:\video\ffmpeg.exe -r 10 -s 1920x1080 -start_number 1 -i C:\...frames\frame_%6d.bmp -vcodec libx264 -crf 25 -pix_fmt yuv420p c:\temp\spiwtmvstf-shuffle\seedname_vorotrans-anim.mp4
```

Use this to:

- Verify the frame rate (`-r 10`), resolution (`-s 1920x1080`), input pattern (`-i ...\frame_%6d.bmp`) and output path.
- Manually paste the command into a terminal to see any error messages ffmpeg emits.
- Ensure that the input files (`frame_000001.bmp`, etc.) actually exist at the specified input path.

---

Following these steps will help isolate whether the failure stems from an incorrect executable path, directory permissions, or an invalid ffmpeg command line. Once corrected, rerun the batch capture to confirm that your MP4 is produced successfully.
