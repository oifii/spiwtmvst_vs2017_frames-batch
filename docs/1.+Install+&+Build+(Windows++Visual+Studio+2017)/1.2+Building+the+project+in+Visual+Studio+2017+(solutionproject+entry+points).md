# 1.2 Building the project in Visual Studio 2017 (solution/project entry points)

This section explains how to open, configure and build the `spiwtmvst_vs2017_frames-batch` project in Visual Studio 2017, and describes its key compilation units and application entry point.

## Opening the Project

1. Clone or download the repository locally.
2. In Visual Studio 2017, choose **File → Open → Project/Solution**.
3. Select the `spiwindowtransparentmidivoroguispectrumtimeframe.vcxproj` file at the root of the repository.

This project contains all source (`.cpp`) and header (`.h`) files needed to build the Win32 desktop application.

## Project Configuration and Dependencies

The `.vcxproj` defines:

- **Include directories** for third-party libraries (FreeImage, PortAudio, PortMidi, FFTW, Oifiilib, Tonic, etc.) under `<AdditionalIncludeDirectories>`.
- **Linker dependencies** pointing to the corresponding `.lib` files (e.g. `FreeImage.lib`, `portaudio_x86.lib`, `spiwavsetlib_vs2017.lib`, `TonicLib.lib`, `winmm.lib`, `opengl32.lib`, etc.).

These settings assume you have built or installed those libraries in the paths referenced by the project.

## Precompiled Header Setup

To accelerate compilation, the project uses a precompiled header:

- `stdafx.h` includes common Windows and library headers.
- `stdafx.cpp` includes only `stdafx.h` and generates the precompiled header (`spiwavwin32.pch`) .
- In the `.vcxproj`, `stdafx.cpp` is marked with `<PrecompiledHeader>Create</PrecompiledHeader>` for all configurations and platforms .

When you build the solution, Visual Studio first compiles `stdafx.cpp` to produce the PCH, then uses it for all other compilation units.

## Compilation Units and Entry Point

### stdafx.cpp

- Includes `stdafx.h` to generate the precompiled header.
- Does not contain application logic; purely for PCH creation .

### spiwindowtransparentmidivoroguispectrumtimeframe.cpp

This file defines the Win32 application entry point:

```cpp
int APIENTRY WinMain(
    HINSTANCE hInstance,
    HINSTANCE hPrevInstance,
    LPSTR    lpCmdLine,
    int      nCmdShow
){
    _set_purecall_handler(myPurecallHandler); // for debugging
    UNREFERENCED_PARAMETER(hPrevInstance);
    UNREFERENCED_PARAMETER(lpCmdLine);
    global_hinstance = hInstance;
    global_startstamp_ms = GetTickCount();

    // Parse command-line arguments...
    // Initialize audio device settings...

    // Create and show each window instance:
    CVoroguiWindow* pVoroguiWindow = DEBUG_NEW CVoroguiWindow(
        L"myvoroguiwindowtitle", hInstance, myclassname.c_str(),
        global_pSynth, wndparampointers, global_dib, global_imagefilenames, global_voroguiclustermode,
        global_x, global_y, global_xwidth, global_yheight,
        global_alpha, global_titlebardisplay, 0
    );
    pVoroguiWindow->Create();
    pVoroguiWindow->Show();
    global_pVoroguiWindow = pVoroguiWindow;

    CVorossWindow* pVorossWindow = DEBUG_NEW CVorossWindow(
        L"myvorosswindowtitle", hInstance, myclassname.c_str(),
        NULL, wndparampointers, global_dib, global_imagefilenames, global_vorossclustermode,
        global_x, global_y, global_xwidth, global_yheight,
        global_alpha, global_titlebardisplay, 0
    );
    pVorossWindow->Create();
    pVorossWindow->Show();
    global_pVorossWindow = pVorossWindow;

    // Pump the Win32 message loop:
    MSG msg;
    HACCEL hAccel = global_acceleratoractive
        ? LoadAccelerators(hInstance, MAKEINTRESOURCE(IDC_SPIWAVWIN32))
        : NULL;
    int status;
    while ((status = ::GetMessage(&msg, NULL, 0, 0)) != 0) {
        if (status == -1) break;
        ::TranslateMessage(&msg);
        ::DispatchMessage(&msg);
    }

    // Cleanup PortAudio, PortMidi, windows and allocated objects...
    return (int)msg.wParam;
}
```

This is the primary application entry point where all window classes are instantiated, shown, and the message loop begins .

## Window Classes and Startup

- Each window type (text, spectrum, image, timeframe, Voronoi variants) derives from `CWindowMultimonitor` or `CWindowParameter`, which in turn derive from the base `CWindow`/`CWindowTransparent`.
- Constructors register their Win32 class via `RegisterClassEx` and create layered, no-activate, transparent windows as specified in their `Create()` calls.
- `CVoroguiWindow` and `CVorossWindow` call `Initialize()` in their constructors to set up DSP visualization parameters and canvas resources .

## Build Steps

1. In Visual Studio 2017, select **Build → Build Solution** (or press F7).
2. Visual Studio will:
3. Compile `stdafx.cpp` to produce the precompiled header (`spiwavwin32.pch`).
4. Compile each `.cpp` with the PCH.
5. Link all object files into the final executable, pulling in the listed third-party `.lib` dependencies.
6. Upon successful build, the output executable can be run directly; it initializes audio, creates visualization windows, and enters the message loop as described above.
